1. Fondasi Arsitektur (IAP vs AOS 8 vs AOS 10)

Pemahaman mendalam mengenai arsitektur kontrol dan penanganan data traffic.

Aruba Instant (IAP)

Arsitektur terdistribusi tanpa controller fisik. Satu AP bertindak sebagai Virtual Controller (VC) yang mengelola konfigurasi seluruh AP dalam satu segmen L2 yang sama.

  • Maksimal 128 AP per kluster L2.
  • Data traffic di-bridge lokal ke port switch.
  • VC terpilih otomatis via master election.
ArubaOS 8 Campus (MC)

Arsitektur terpusat menggunakan Mobility Conductor (MCR) untuk manajemen dan Mobility Controller (MC) untuk pemrosesan traffic data.

  • Traffic klien di-tunneling lewat GRE (IP 47) ke MC.
  • PEF Stateful Firewall berjalan di controller.
  • Clustering aktif tanpa client disassociation saat failover.
Aruba Central AOS 10

Arsitektur cloud-native. Manajemen dan optimasi RF (AirMatch) sepenuhnya dipindahkan ke cloud microservices Aruba Central.

  • Bridge Mode: AP melakukan local forwarding mandiri.
  • Microbranch: AP membentuk tunnel IPsec langsung ke WAN Gateway.
  • Eliminasi Mobility Conductor lokal.

2. Setup Awal Perangkat (Day-0 & Day-1)

Langkah inisialisasi dari perangkat baru di kardus hingga beroperasi normal.

A. Setup Kluster Aruba Instant (IAP)
  1. Nyalakan AP dan sambungkan ke switch access yang memiliki DHCP server.
  2. Koneksikan laptop ke SSID default Set-Me-Up-xx:xx:xx.
  3. Buka browser ke https://instant.arubanetworks.com:4343 (default login: admin / serial number).
  4. Kunci Virtual Controller IP: Masuk ke System > General > Virtual Controller IP. Masukkan alamat IP statis untuk cluster management.
  5. Buat SSID di menu Networks > New: pilih Key Management WPA2/WPA3 Personal atau WPA2-Enterprise dengan server ClearPass.
B. Setup Initial Mobility Controller (AOS 8 Console)

Hubungkan kabel console serial (9600-8-N-1) ke controller, lalu jawab dialog wizard berikut:

3. Matriks Konversi Mode AP (Conversion Playbook)

Sintaks dan prosedur konversi antar persona IAP, Campus AP, dan Central AOS 10.

IAP → Campus AP (AOS 8 MC)

Eksekusi via CLI Virtual Controller:

IAP# convert-aos-ap cap <IP-Controller>

AP akan me-reboot, menarik image firmware dari controller, dan masuk ke mode tunnel.

Campus AP → IAP Standalone

Eksekusi via bootloader console AP (apboot>):

apboot> purgeenv
apboot> clear os
apboot> saveenv
apboot> reset
IAP / CAP → Aruba Central (AOS 10)

Onboarding otomatis via cloud:

  1. Hapus AP dari database controller lama jika sebelumnya berstatus CAP.
  2. Assign subscription Foundation License di GreenLake.
  3. Pastikan port outbound TCP 443 terbuka ke internet.
  4. Reboot AP → Activate mengarahkan AP ke Central → Upgrade OS 10 otomatis.
Central AOS 10 Rollback → AOS 8

Prosedur pelepasan lisensi cloud:

  1. Unassign lisensi Central dari AP di portal GreenLake.
  2. Keluarkan AP dari grup AOS 10 di dashboard Central.
  3. Buka console AP dan flash image firmware AOS 8 via command upgrade os.

6. 802.1X, ClearPass CPPM & Dynamic Authorization (CoA)

Isolasi handshake EAP/RADIUS dan penanganan konflik port RFC 3576.

A. Decoder `show auth-tracebuf` CLI Trace
(MC-01) # show auth-tracebuf mac 48:2a:e3:11:22:33
server-timeout

RADIUS Server mati, port UDP 1812 diblokir, atau Shared Secret mismatch.

eap-failure

Kredensial AD salah, akun terkunci, atau Policy di ClearPass tidak cocok.

client-timeout

Klien Android/iOS menolak CA Certificate ClearPass atau prompt trust di-cancel.

B. Konflik Port RFC 3576 CoA: UDP 3799 vs 5999

ArubaOS legacy menggunakan port proprietary UDP 5999, sedangkan standar RFC adalah UDP 3799. Jika fitur Disconnect atau Role Change ClearPass gagal, verifikasi dengan command:

(MC-01) # show rfc3576 statistics
