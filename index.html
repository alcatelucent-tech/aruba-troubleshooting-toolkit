• Fondasi Arsitektur Aruba Wireless

Perbandingan arsitektur control plane, data plane forwarding, dan model arsitektur di tiga platform utama.

Aruba Instant (IAP) Controllerless

Virtual Controller (VC) Architecture

Tidak memerlukan appliance controller fisik. Satu AP dalam satu subnet L2 terpilih secara dinamis sebagai Virtual Controller (VC) yang mengelola konfigurasi seluruh AP anggota (Slave).

  • Master Election: Berdasarkan AP dengan waktu uptime paling lama, kapasitas CPU tertinggi, atau preference flag.
  • Image Sync: VC mendistribusikan firmware image ke semua AP anggota secara otomatis.
  • Forwarding: Bridge lokal langsung ke port switch access.
ArubaOS 8 (AOS 8) Controller-Centric

Conductor & Controller Hierarchy

Memisahkan peran manajemen dan forwarding. Mobility Conductor (MCR) bertindak sebagai otak konfigurasi terpusat, sedangkan Mobility Controller (MC) memproses data plane.

  • Encapsulation: Traffic client dibungkus tunnel GRE (IP Protocol 47) dari AP ke Controller.
  • Stateful PEF Firewall: Kebijakan peran (User Roles) dieksekusi di Controller.
  • Clustering: Mendukung Active-Active clustering untuk Seamless Failover tanpa client drop.
Aruba Central (AOS 10) Cloud-Native

Microservices Cloud Architecture

Menghilangkan kebutuhan Conductor lokal. Semua konfigurasi, AirMatch RF, dan analitik AI dijalankan langsung dari cloud Aruba Central.

  • Bridge Mode: AP berfungsi seperti IAP tingkat tinggi, bridge langsung ke LAN lokal.
  • Tunnel / Microbranch Mode: AP membentuk tunnel IPsec langsung ke Aruba Gateway (VPNC/Campus Gateway).
  • ZTP: Onboarding otomatis melalui Aruba Activate dan TPM chip.

• Inisialisasi & Setup Awal (Day-0 & Day-1 Setup)

Langkah teknis mengkonfigurasi perangkat dari kardus baru hingga siap melayani klien.

IAP SETUP

Setup Cluster Aruba Instant (IAP)

  1. Hubungkan kabel Ethernet AP ke switch yang memiliki DHCP server dengan akses internet.
  2. Tunggu LED radio menyala hijau/berkedip. Hubungkan laptop ke SSID default: Set-Me-Up-xx:xx:xx.
  3. Buka browser dan akses https://instant.arubanetworks.com:4343 atau IP DHCP AP. Login default: user admin, password: admin atau serial number AP.
  4. Kunci Virtual Controller IP: Masuk ke System > General > Virtual Controller IP. Masukkan IP statis dalam subnet yang sama agar GUI tidak hilang saat AP master reboot.
  5. Buat SSID baru di menu Networks > New: Tentukan SSID Name, pilih Key Management (WPA2/WPA3 Personal atau WPA2-Enterprise dengan server RADIUS ClearPass).
AOS 8 SETUP

Setup Awal Mobility Controller (AOS 8 CLI Setup Wizard)

Koneksikan kabel serial console (Baud 9600) ke controller. Saat prompt wizard `Auto-provisioning` muncul, ketik no untuk masuk ke setup manual:

# Cuplikan parameter dialog setup awal controller:

Enter Netmask: 255.255.255.0
Enter Default Gateway IP: 10.100.1.1
Enter Conductor IP: 10.100.1.5 (jika Managed Node)
Enter Country Code: ID (Indonesia - 360)
CENTRAL AOS 10

Onboarding Perangkat ke Aruba Central Cloud

  1. Buka portal HPE GreenLake (common.cloud.hpe.com), buka menu Device Management.
  2. Klik Add Devices > masukkan Serial Number dan MAC Address perangkat atau unggah file manifest pesanan (CSV).
  3. Pilih aplikasi Aruba Central dan assign subscription token (Foundation AP License).
  4. Buka dashboard Aruba Central > Masuk ke Organization > Groups > Buat Group baru dengan tipe arsitektur AOS 10.
  5. Masukkan AP ke dalam Group tersebut. Saat AP pertama kali terhubung ke internet dan menghubungi Activate, firmware akan otomatis ter-upgrade ke image AOS 10 dan menarik konfigurasi Group.

• Matriks & Prosedur Konversi Mode AP

Panduan langkah demi langkah mengubah persona AP antara IAP, Campus AP (Controller), dan Central Cloud.

1. IAP → Campus AP (AOS 8 Controller)

GUI / CLI

Mengubah Instant AP agar mencari dan join ke Mobility Controller.

# Cara CLI dari VC Instant AP:
IAP# convert-aos-ap cap <IP-Controller>
# Atau via WebUI IAP:
Maintenance > Convert > Pilih "Campus AP" > Masukkan IP Controller > Convert Now

Catatan: AP akan reboot, mengunduh image CAP dari controller, dan membutuhkan persetujuan CPsec whitelist.

2. Campus AP → IAP Standalone

apboot Console

Berlaku untuk model Unified AP (seri AP-3xx, AP-5xx, AP-6xx) yang sebelumnya terdaftar di Controller.

# Hubungkan console, reboot AP, tekan Enter saat hitung mundur:
apboot> purgeenv
apboot> clear os
apboot> saveenv
apboot> reset

Jika image IAP hilang dari partisi flash, siapkan tftp server lalu jalankan tftpboot image Instant.

3. IAP / CAP → Aruba Central (AOS 10)

Activate ZTP

Proses migrasi otomatis dari controller/IAP lama menuju cloud-managed AOS 10.

  1. Hapus AP dari database controller lama jika sebelumnya berstatus CAP (clear ap database ap-name <name>).
  2. Assign lisensi Foundation di GreenLake Device Manager.
  3. Pastikan port firewall outbound TCP 443 terbuka ke cloud Activate.
  4. Reboot AP. AP akan kontak Activate → redirect ke Central → download firmware AOS 10.

4. Central AOS 10 → Rollback ke AOS 8

Downgrade Recovery

Mengembalikan AP dari kontrol Central kembali ke mode Instant AP atau Controller lokal.

  1. Unassign Lisensi: Lepaskan lisensi Central dari AP di portal GreenLake (agar Activate tidak menariknya kembali).
  2. Di dashboard Central, pindahkan AP keluar dari Group AOS 10.
  3. Buka console AP, lakukan factory reset atau downgrade image via CLI:
    # upgrade os <url-image-aos8>

• Triage & Troubleshooting Lapangan (Day-2 Diagnostics)

Alur isolasi masalah daya, penemuan AP, kegagalan asosiasi klien, sertifikat 802.1X, hingga roaming RF.

1. Daya & Negosiasi PoE Switch (LLDP / CDP Power Budget)

L1 / Power

AP generasi Wi-Fi 6/6E (AP-535, AP-555, AP-635) membutuhkan daya standar PoE+ (802.3at / 30W) atau PoE++ (802.3bt). Jika switch hanya menyuplai 802.3af (15.4W), radio 5GHz/6GHz akan otomatis mati (*Power Restricted Mode*).

# Verifikasi daya yang diterima AP dari switch:
(MC-01) # show ap power-mgmt-status ap-name <AP-Name>
# Di sisi switch Aruba-CX:
switch# show power-over-ethernet <port>

2. Decoder Flags: `show ap database` (AOS 8)

Flag Status Akar Masalah Perintah Perbaikan
I Inactive AP ditolak whitelist CPsec atau tunnel UDP 4500 drop. whitelist-db cpsec modify mac-address <mac> state approved
D Dirty Konfigurasi AP tidak sinkron dengan database Conductor. ap-regroup ap-name <name> <group>
U Unprovisioned AP baru terdeteksi dengan nama default dan belum di-provisioning. provision-ap ap-name <mac> ap-group <group>
R RAP Remote AP aktif via tunnel IPsec eksternal. Operasi normal untuk RAP.

3. 802.1X & ClearPass CPPM Troubleshooting

Security Triage

Isolasi titik putus autentikasi Enterprise menggunakan show auth-tracebuf di controller:

server-timeout

RADIUS Server mati, port UDP 1812/1813 terblokir firewall, atau RADIUS Secret tidak cocok.

eap-failure / rad-reject

Password user salah, akun Active Directory terkunci, atau Policy di ClearPass tidak match.

client-timeout

HP Android/iOS menolak trust sertifikat EAP ClearPass, atau user membatalkan prompt popup.

Trap RFC 3576 / CoA: UDP 3799 vs 5999

ClearPass default NAD Aruba menggunakan port lama UDP 5999, sedangkan standar RFC adalah UDP 3799. Cek di controller: show rfc3576 statistics.

Trap Android 11+ & iOS CA Trust

Klien modern tidak mengizinkan opsi "Do not validate" CA Certificate. Domain FQDN ClearPass (misal: cppm.domain.com) wajib diisi di supplicant perangkat.

4. RF Optimization & Roaming (ClientMatch & AirMatch)

RF Triage

Mengatasi masalah sticky client (perangkat tetap terhubung ke AP jauh dengan RSSI buruk meskipun ada AP dekat):

# Cek histori steering ClientMatch untuk MAC tertentu:
(MC-01) # show ap client-match-history client-mac <mac-address>
# Cek kalkulasi kanal dan daya pancar radio dari AirMatch:
(MCR) # show airmatch report ap-name <AP-Name>
